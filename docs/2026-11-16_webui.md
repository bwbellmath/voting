# Election Explorer web UI (2026-11-16)

An interactive map and plot explorer for the 1976–2020 results and the compass-agent simulations. Code is in `webui/` (static page, no backend).

## Run

```bash
.venv/bin/python scripts/run_methods.py          # ~4 min, writes outputs/compass/methods/contest_wins.npz
.venv/bin/python scripts/run_desertion.py        # ~6 min, writes outputs/compass/desertion/contest_wins.npz
.venv/bin/python scripts/build_webui_geo.py      # ~5 min, downloads ~470 MB once into webui/.geo_cache
.venv/bin/python scripts/build_webui.py          # writes webui/data/app.json (3.9 MB)
.venv/bin/python -m http.server 8765 -d webui --bind 127.0.0.1    # open http://127.0.0.1:8765
```

`webui/vendor/` holds d3 7.9.0 and topojson-client 3.1.0; `webui/data/geo/states.json` is us-atlas 3.0.1.

## What it does

| Part | Behaviour |
|---|---|
| Map | States, congressional districts (per Congress, so they change with the year), or one hexagon per House seat. Scroll or use the buttons to zoom; drag to pan. |
| Colour by | Winner, two-party margin, third-party vote share, compass lean, simulated win chance, chance the result changes. |
| Granularity | House is by district. Senate and President are by state, so a district or hexagon shows its state's result. In state view, House colours blend the state's seats. |
| Selection | Click any number of states, districts or hexagons. With nothing selected, every plot is for the whole country. |
| Results tab | Seats and vote share for the chosen year, vote share over time, and every contest with each candidate's win chance. |
| Demographics tab | Model-inferred party identification, voter-type mix and axis position, next to Gallup's national survey. |
| Simulations tab | Seats over time as a line chart (actual, plus any simulated methods) or as a histogram heatmap. A table gives the numbers for the chosen year. |
| Year | Clicking a year in any plot moves the map to that election. |
| Link | The page address records the full view, so a view can be bookmarked or shared. |

### Histogram heatmap

- x = election, y = seats won, colour = probability of winning exactly that many seats.
- Three colour channels, one per party class (Democrat, Republican, third party), so overlapping distributions mix.
- Dark theme: RGB light on black (blue, red, green; D + R overlap is magenta). Light theme: CMY-style ink on white. Either can be forced.

### How seat distributions are computed

The simulations store, for every contest and method, how often each candidate won in 200 runs. Contests are simulated independently, so the seat distribution of any selection is the exact sum of independent contest outcomes (a Poisson-binomial), computed in the browser. National averages match `outputs/compass/methods/seats_summary.csv`.

## Limits and pins

- **State legislative elections: not in the repository.** Pinned. The UI would need a results file per chamber and district boundary layers (Census `sldu`/`sldl`), and the compass has no fitted state-legislative units.
- **Demographics:** no census data below national level; the tab shows model inferences only.
- **President is not simulated.** Only the random ballot differs from the real result. Seats are electoral votes, winner-take-all (Maine and Nebraska splits ignored).
- **2020 districts** use the 116th Congress lines; North Carolina's 2020 redraw is missing.
- **Missing House contests** show as "no data": 13 Texas districts in 1996 and 4 in 2006 (court-ordered special elections, excluded as specials) and FL-25 in 2020 (unopposed, absent from the returns).
- **A selected district is followed by number**, not by geography, across redistricting.
- **Sitting Senate chamber** is incomplete before 1980.
- **District layers for 1982–2014 are 2–2.7 MB each** (40 MB in total). The source shapes for those years do not share vertices between neighbours, so they simplify less well.
- `webui/data/` and `webui/.geo_cache/` are generated and git-ignored.
- **Not tested by automated clicks.** Views were checked by loading saved addresses in headless Chrome; clicking and zooming use the same code paths but were not driven by a test.
